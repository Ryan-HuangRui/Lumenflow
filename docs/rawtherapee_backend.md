# RawTherapee 5.11 headless backend

Lumenflow invokes the same RawTherapee processing engine used by the GUI via
`rawtherapee-cli`.  The CLI is profile-driven: a processing profile (`.pp3`)
contains the module state, while command-line switches select the input,
profile stack, and final output container.

## State and safety model

`scripts/rawtherapee_pp3.py` implements `lumenflow.rawtherapee-pp3.v2`:

- profiles are parsed with bounded UTF-8 validation;
- later profiles override only fields they contain;
- unknown sections and fields are retained, so a profile generated by a newer
  RawTherapee release is not silently reduced to the fields Lumenflow knows;
- malformed profiles, oversized inputs, non-finite values, and multiline values
  fail closed;
- when a preview artifact supplies explicit `state_inputs`, the compiler
  verifies every path and SHA-256, merges those bytes into the generated PP3,
  and executes the embedded snapshot rather than reading a mutable sidecar.

For legacy intents without explicit inputs, a regular `RAW.pp3` sidecar is
discovered and checked against the preview state hash when present.  A base
profile used only by an old preview artifact cannot be reconstructed from a
hash alone; new workflows should carry `preview_basis.state_inputs`.

## Current semantic mapping

The vendor-neutral intent compiler currently maps and tests:

| Intent field | RawTherapee PP3 field |
| --- | --- |
| exposure compensation | `[Exposure] Compensation` |
| brightness / contrast / saturation | `[Exposure] Brightness/Contrast/Saturation` |
| black point | `[Exposure] Black` |
| highlight recovery | `[Exposure] HighlightCompr` |
| shadow lift | `[Exposure] ShadowCompr` |
| temperature / green multiplier | `[White Balance] Temperature/Green` |
| pixel crop | `[Crop] X/Y/W/H` |

The compiler rejects unknown semantic fields.  This is intentional: GUI labels
are not stable PP3 keys and guessing a mapping can produce a plausible but
wrong image.

The lower-level `compile_profile_text()` API can merge a complete, fixture-
verified section/key mapping for additional RawTherapee modules while retaining
the starting profile fields.  This is a profile-import/merge primitive, not an
agent-facing native-module API: preserving unknown fields from an input PP3 does
not verify that an agent-authored value is correct for RawTherapee 5.11.

`EditIntent v2` currently exposes only the vendor-neutral fields in the table
above.  It does not expose `rawtherapee_native`, `style.rawtherapee.sections`,
or any other arbitrary PP3 escape hatch.  Full native-module authoring remains
future work and must first define a strict bounded schema (for example,
`style.rawtherapee.sections`) backed by versioned 5.11 fixtures and CLI render
tests before it is exposed to agents.

## Output containers

`render_raw.build_rawtherapee_command()` supports the native 5.11 output
options:

- JPEG quality 1–100 and chroma subsampling 1/2/3;
- PNG 8/16-bit integer;
- uncompressed or deflate-compressed TIFF;
- TIFF 8-bit integer, 16-bit integer, 16-bit float, or 32-bit float.

The current `EditIntent v2` default remains JPEG for compatibility.  Final
export callers can request the other containers through the renderer command
builder while the same PP3 processing state is used.

## Verification

Unit coverage:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest \
  tests.test_rawtherapee_pp3 \
  tests.test_photo_pipeline \
  tests.test_preview_provider \
  tests.test_edit_intent_execution
```

The integration fixture and the installed tool are recorded in the capability
contract (`scripts/backend_capabilities.py`).  The three local Bangkok RAW
copies used for live checks are outside the repository; the NAS originals are
never modified.

Still outside the verified semantic slice: local/AI masks, advanced color
tools, full tone-curve authoring, lens/denoise/sharpen module synthesis, and
catalog writes.  These require versioned PP3 fixtures before being enabled.
